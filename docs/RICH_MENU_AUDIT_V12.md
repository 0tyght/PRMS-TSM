# PRMS-TSM Rich Menu V12 — Full UX, Workflow and Performance Audit

วันที่ตรวจ: 6 สิงหาคม 2026

## เป้าหมาย

V12 ปรับระบบจาก “สร้าง Rich Menu ใหม่แทบทุกครั้งที่กด” ให้เป็นระบบเมนูที่ใช้งานจริงได้เร็ว อ่านง่าย และมีเส้นทางไม่ซ้ำซ้อน โดยยังคงข้อกำหนดเดิมว่า **ตัวเลือกทั้งหมดอยู่ใน Rich Menu ด้านล่าง ไม่แสดงลิสต์ปุ่มซ้ำในข้อความแชต และไม่เปิด LIFF/เว็บไซต์**

## สาเหตุที่ V11 ช้าและหน่วง

1. ทุกการกดเมนูเรียกขั้นตอนหนักต่อเนื่อง: render PNG → create Rich Menu → upload รูป → link ให้ผู้ใช้ → บันทึกฐานข้อมูล
2. เมนูหลักและเมนูย่อยแบบคงที่ยังต้องรอ Webhook/API ก่อนเปลี่ยนหน้า
3. ไม่มี cache กลางตามเนื้อหาเมนู จึงสร้างรูปและ Rich Menu ซ้ำ แม้หน้าตาและ action เหมือนกัน
4. การตอบข้อความและการเปลี่ยน Rich Menu ไม่ได้ถูกจัดการเป็นงานคู่ขนานอย่างชัดเจน
5. การกดเร็วหลายครั้งอาจทำให้คำสั่ง link เมนูเรียงสลับหรือเสร็จผิดลำดับ
6. มีการ sync Rich Menu รุ่นเก่าจาก `citizenExperience.js` ซึ่งอาจเขียนทับ V11

## สิ่งที่แก้ใน V12

### ความเร็ว

- เพิ่ม cache ตาราง `line_rich_menu_assets` โดยใช้ SHA-256 fingerprint ของหน้าเมนู
- หน้าเดิมใช้ Rich Menu ID เดิม ไม่ render/create/upload ซ้ำ
- ใช้ in-memory LRU image cache ลดการ render ซ้ำภายใน process
- เพิ่ม per-user queue ป้องกันการกดเร็วแล้วเมนูสลับผิดลำดับ
- เพิ่ม per-fingerprint creation lock ป้องกันหลายผู้ใช้สร้าง asset เดียวกันพร้อมกัน
- เพิ่ม timeout ให้ LINE API และ reply API
- เปลี่ยนการตอบข้อความกับการอัปเดตเมนูให้ทำพร้อมกัน
- pre-warm เมนูหลักและเมนูย่อยทุกหน้าเมื่อเปิด API
- ไม่ลบ Rich Menu เก่าทันทีทุกครั้ง แต่ cleanup เฉพาะ dynamic cache ที่หมดอายุและไม่มีผู้ใช้อ้างอิง

### การสลับเมนูทันที

หน้าเมนูหลักของเจ้าของและเมนูย่อย 5 หมวดใช้ Rich Menu Alias + `richmenuswitch`:

- สัตว์ของฉัน
- สุขภาพสัตว์
- แจ้งสถานะสัตว์
- คำขอของฉัน
- ข้อมูลเจ้าของ

การกดหมวดเหล่านี้เปลี่ยนหน้าที่ฝั่ง LINE โดยตรง ไม่ต้องรอ API สร้างเมนูใหม่ ส่วนงานที่ต้องอ่านฐานข้อมูลหรือบันทึกข้อมูลยังใช้ postback ตามปกติ

### ตัวหนังสือและดีไซน์

- เปลี่ยนจากการ์ด 3 คอลัมน์เป็น 2 คอลัมน์
- ขั้นตอนที่มี 1–3 ตัวเลือกใช้การ์ดเต็มความกว้าง
- ขยายชื่อเมนูหลักเป็น 88 px และชื่อการ์ด 78–94 px ที่ภาพต้นฉบับ 2500×1686
- จำกัดข้อความไม่เกิน 2 บรรทัด พร้อมตัดคำแบบไทย
- ใช้สีตามความหมายของงาน ไม่ใช้สีตามลำดับช่อง
- เพิ่ม icon vector ไม่พึ่ง emoji font
- คงตำแหน่ง `ย้อนกลับ / เมนูหลัก / ยกเลิกรายการ` ที่แถวล่างทุก workflow
- ปุ่มหน้าก่อน/หน้าถัดไปอยู่ใน header จึงไม่แย่งช่องรายการจริง

## การลด Workflow ซ้ำซ้อน

### เมนูหลักเจ้าของเดิม

- สัตว์ของฉัน
- เพิ่มสัตว์
- สุขภาพสัตว์
- แจ้งสถานะสัตว์
- คำขอของฉัน
- ข้อมูลเจ้าของ

`เพิ่มสัตว์` ซ้ำกับเมนู “สัตว์ของฉัน” จึงย้ายเข้าเมนูย่อย และใช้ช่องที่เหลือเป็น `รายการที่ต้องทำ` ซึ่งมาจากข้อมูลจริงของผู้ใช้

### เมนูย่อย V12

**สัตว์ของฉัน**
- ดูสัตว์ทั้งหมด
- เพิ่มสัตว์ใหม่
- แก้ข้อมูลสัตว์

**สุขภาพสัตว์**
- แจ้งวัคซีน
- แจ้งทำหมัน
- ดูข้อมูลสุขภาพ

**แจ้งสถานะสัตว์**
- แจ้งสูญหาย
- แจ้งพบแล้ว
- แจ้งเสียชีวิต
- โอนเจ้าของ

**คำขอของฉัน**
- ต้องส่งข้อมูลเพิ่ม
- กำลังตรวจสอบ
- ดำเนินการเสร็จแล้ว
- คำขอทั้งหมด
- ติดตามเลขอ้างอิง

**ข้อมูลเจ้าของ**
- ดูหรือแก้ข้อมูล
- แก้ตำแหน่งบ้าน
- ติดต่อเทศบาล

### จัดการสัตว์รายตัว

เดิมกด “สุขภาพสัตว์” จากสัตว์ตัวหนึ่งแล้วกลับไปเลือกสัตว์ซ้ำอีกครั้ง V12 เปลี่ยนเป็นเมนูรายตัวโดยตรง:

- ดูรายละเอียด
- แก้ข้อมูลสัตว์
- แจ้งวัคซีนของตัวนี้
- แจ้งทำหมันของตัวนี้
- แจ้งสถานะของตัวนี้

## ข้อมูลผิดพลาดที่แก้

1. รายละเอียดสัตว์ใช้ `STATUS_LABELS` ของสถานะคำขอ แก้เป็น `PET_STATUS_LABELS`
2. คำว่า “เปิดเมนูสุขภาพสัตว์” เคยถูกคำว่า “เมนู” จับเป็นเมนูหลักก่อน แก้ให้คำสั่งเฉพาะมีลำดับสูงกว่า
3. ผู้ใช้ที่ยังไม่เชื่อมทะเบียนกด “คำขอของฉัน” เคยเข้าหน้าเจ้าของ แก้ให้ไปติดตามเลขอ้างอิง
4. หมู่บ้านเกิน 12 รายการเคยหาย เพราะ `quickReply()` ตัดไว้ 13 ปุ่ม แก้ให้เก็บ `_wizardItems` ครบทั้งหมดสำหรับ Rich Menu แล้วส่งให้ LINE เฉพาะรายการที่ LINE รองรับ
5. รายชื่อสัตว์เคยแบ่งหน้ารอบแรก 8 รายการ แล้วถูก Rich Menu แบ่งหน้าอีกรอบ ทำให้เป็น nested pagination แก้ให้โหลดรายการเจ้าของครั้งเดียวและแบ่งหน้าเพียงชั้นเดียวใน Rich Menu
6. ปุ่มคำขอหลายรายการเคยมีชื่อซ้ำ ใช้ `displayText` ที่มีเลขอ้างอิงเป็น label ใน Rich Menu
7. รายการคำขอเดิมอ่านมาเพียง 200 รายการแล้วกรองในหน่วยความจำ ทำให้คำขอเก่าหรือคำขอบางสถานะหายได้ V12 เปลี่ยนเป็นนับและแบ่งหน้าจากฐานข้อมูลจริงครั้งละ 4 รายการ พร้อมหน้ารายละเอียด ส่งข้อมูลเพิ่ม ยกเลิก และกลับหน้ารายการเดิม
8. ตัด Legacy Flex List และ Module Bridge ออกจาก runtime และชุดทดสอบ
9. `syncRichMenuForLineUser()` รุ่นเก่าเลิกใช้ Rich Menu ID จาก environment และใช้ V12 main menu โดยตรง
10. Flex สรุปสถานะไม่วางปุ่มซ้ำในข้อความอีกต่อไป

## Workflow ที่ตรวจ

- REGISTER — ลงทะเบียนสัตว์ใหม่
- LINK — เชื่อมทะเบียนเดิมกับ LINE
- TRACK — ติดตามเลขอ้างอิง
- VACCINATION — แจ้งวัคซีน
- STERILIZATION — แจ้งทำหมัน
- PET_STATUS — สูญหาย / พบแล้ว / เสียชีวิต
- PET_UPDATE — แก้ข้อมูลสัตว์
- OWNER_TRANSFER — โอนเจ้าของ
- LOCATION — ตำแหน่งบ้าน
- PROFILE_UPDATE — แก้ข้อมูลเจ้าของ
- RESUBMIT — ส่งข้อมูลเพิ่มเติมตามเจ้าหน้าที่ร้องขอ
- ยกเลิกคำขอและยกเลิก workflow ที่ค้างอยู่
- กลับขั้นตอนก่อนหน้าและกลับเมนูหลัก
- รายการหมู่บ้าน สัตว์ และคำขอหลายหน้า
- รายการคำขอแบ่งหน้าจากฐานข้อมูลจริง พร้อมหน้ารายละเอียดและกลับหน้าที่มา
- กล้อง คลังภาพ ตำแหน่ง และ Date Picker

## การตรวจอัตโนมัติ

- action literal ทุกตัวมี handler

- LINE reply และ Rich Menu task ทำงานคู่ขนาน

ผลจากชุดที่จัดทำ:

- emitted actions: 28
- unresolved actions: 0
- legacy/unsafe tokens: 0
- focused V12 tests: 25/25 ผ่าน

ตัวติดตั้งจะรัน `npm test --workspace @prms/api` กับโปรเจกต์จริงอีกครั้งก่อน sync ให้ผู้ใช้จริง หากมีเทสต์ใดไม่ผ่านจะหยุดและเก็บไฟล์สำรองไว้ ไม่เปิดใช้แพตช์แบบเงียบ ๆ
